## 1. What ojuny is

ojuny is a NixOS-based "distro" / set of dotfiles, built as a response to
omarchy. omarchy is an opinionated set of dotfiles on Arch with Hyprland and a
custom quickshell, coded almost entirely by AI. ojuny provides the same
experience but built on Nix, using non-vibecoded tooling.

ojuny has a layered shape:

1. **ojuny-desktop** (separate repo, in progress). A wrapped desktop package
   providing a pre-configured mangoWM and Dux Shell, plus NixOS and
   home-manager modules that expose user-relevant mangoWM and Dux Shell
   settings as `desktop.ojuny.*` options.
2. **ojuny-template** (this repo). A forkable template flake plus a setup
   script that generates `hardware.nix` and `user.nix`. Designed entirely
   around the nix-settings-gui settings menu.
3. **ojuny installer ISO** (future repo). An installer that performs the same
   steps as the template flake.

ojuny is based on the mangoWM desktop config at
`~/repos/nixos-configs/dendrite` (the x1carbon host in particular), uses the
same dendritic pattern, and excludes all G13 and personal workflow tooling.

## 2. This repo's role

ojuny-template is the starting point a new ojuny user forks. It must:

- Contain a complete system config flake using the dendritic pattern.
- Be designed entirely around the nix-settings-gui settings menu, so every
  user-relevant knob is editable from that GUI.
- Provide a setup script that generates `hardware.nix` and `user.nix`.
- Contain no personal, dev-specific, or project-specific data.

## 3. Design principles

Binding for the rest of the spec.

1. **Generalized.** No user names, hostnames, disk UUIDs, SSH keys, hashed
   passwords, personal paths, or personal repositories in tracked files.
   Everything personal is generated by the setup script or edited in the GUI.
2. **Settings-menu-first.** The nix-settings-gui menu is the primary design
   surface. Any user-relevant setting must be reachable as an `@option` on a
   page, and page layout is designed before Nix is written.
3. **One file per settings page.** A settings page equals one `.nix` module
   file equals one `@menu`. All components for that page's settings (NixOS
   module, home-manager module, packages, services, config) live in that file,
   even when it becomes large.
4. **Dendritic.** flake-parts plus import-tree, same as dendrite. Each page
   file contributes `flake.modules.nixos.<page>` and/or
   `flake.modules.homeManager.<page>`.
5. **Names carry ordering.** Category folders are numbered `01-`, `02-`, ...
   and page files are numbered within them. In the GUI the section heading is
   the `@menu` `category` string (its numeric prefix is shown) and the page
   order within a section is the `@menu` `order` value.

## 4. Inputs

- `nixpkgs` (nixos-unstable)
- `flake-parts`
- `import-tree`
- `home-manager`
- `ojuny-desktop` (mangoWM + Dux Shell and the `desktop.ojuny.*` options)
- `nix-settings-gui` (the settings menu)
- `nix-regedit` (registry-editor style GUI for flakes)
- `nix-shell-gui` (temporary `nix run`/`nix shell` app store)
- `simple-nix-update-gui` (update GUI, state daemon, tray)
- `stylix`
- `nixos-hardware` (optional device profiles)
- `base16-schemes` (theme presets)

The four `nix-*` tools are github:SDG-Den flakes and are already wired into
dendrite, so the template reuses them.

No `disko` in the template: partitioning is manual and the generated
`hardware.nix` is used (D2a). The Ojuny installer uses disko for both ISO paths.

## 5. Non-goals

- No G13 driver or config.
- No sops/secrets store.
- No server hosts, deploy-rs targets, Hydra, nix-serve, glusterfs, or binary
  cache infrastructure.
- No personal users (den, noodle, joni, olaf, reena) or their per-user splits.
- No "noodle" variants of mango, dankshell, stylix, or fastfetch.
- No AI defaults. Opt-in registry patches may provide a local model server and harness.

## 6. Decisions

Resolved (full list in 02, section 5): mangoWM + Dux Shell only (D1a); manual install,
generated `hardware.nix` (D2a); template options under `ojuny.*` (D3a);
`@menu`-less files are ignored by the GUI (D5); generated files under `modules/`
(D6a); one file per page declaring its own nixos/home-manager modules (D7a);
dedicated login page (D9a); all update tooling in `updates.nix` (D10); fonts in
style (D11a); Steam built in with Prism Launcher as an opt-in registry patch (D12); system-specific settings in the system
directory (D13a); bash setup script (D14a); stateVersion never exposed (D15a);
no rebuild from the script (D16); fastfetch with `fastfetch-den` default and
`user` as default user (D17); experimental-features flag until the applied config
enables them (D18a).
